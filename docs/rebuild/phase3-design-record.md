# Phase 3 — Architecture design record

> How `ARCHITECTURE.md` and `PLAN.md` were produced (rebuild playbook Phase 3), and the alternatives considered and rejected. Generated from the judge-panel workflow so the *why* behind the chosen design is not lost.

## Method

Three architects each designed a complete rebuild from `SPEC.md` under a different organizing principle, blind to one another. A three-judge panel scored all three on five axes (spec-completeness, simplicity, rebuild-feasibility, invariant-safety, seam-swappability). A synthesizer took the top-ranked backbone and grafted the best ideas the panel flagged from the runners-up. An adversarial critic then reviewed the synthesized documents against the spec and returned required fixes, all of which were applied before commit.

_(One judge, `evolvability`, dropped on a mid-response connection error; the two completing judges agreed on the ranking, so the outcome is unaffected.)_

## The three proposals considered

### SwartzNet Rebuild — "Keep the Seams, Kill the Defect Classes"

**Organizing principle.** The legacy's three structural bets are sound and stay: strict three-layer search isolation (each layer owns its own response type, reconciled only at the edge), one `daemon.New` wiring point, and an `httpapi` with zero subsystem imports (narrow interfaces + its own DTOs). The rebuild's entire job is to convert the §6 defect classes from "possible" into "unrepresentable" by relocating each defect's root cause into a single small owner: capability-on-wire drift dies because one `capability.Announced()` function is the *only* producer of the services mask (wire and `/aggregate` alike); publisher-bit clobber dies because operator-settable sharing prefs and daemon-owned runtime bits are different types the HTTP setter physically cannot reach; sequential search dies because reconciliation moves into one concurrent `searchmux` shared by every frontend; admission-inversion dies because the bootstrap policy becomes typed rules that default-deny. Everything else is evolution of the legacy package map, not reinvention.

**Invariant strategy.** All four hard invariants are enforced by structure, not discipline. Invariant #1 (mainline wire compat) is the load-bearing one and gets three overlapping guards. First, every byte that can reach a non-SwartzNet observer is produced by a codec in a leaf package (record, swarmsearch/wire, dhtindex/schema, signing) with golden-vector tests — no wire bytes are assembled ad hoc in engine or daemon. Second, capability.Announced() is the single producer of the services mask, so the advertised capability set is provably a pure function of (operator prefs, build facts) and can never claim a feature the build lacks or leak a downgrade the operator made. Third — the key testability move — the `wirecompat` suite (MiniPeer that can impersonate a vanilla client by sending an empty LTEP m-dict, plus a pinned anacrolix v1.61.0 vanilla client) is promoted into the CI merge gate and asserts the matrix directly: a peer that never advertised sn_search receives zero sn_search frames, a vanilla client fetches metadata via BEP-9 and completes a download from us, BEP-44 items are byte-indistinguishable from anyone's, and signed/unsigned .torrent twins share one infohash (signing decodes as map[string]bencode.Bytes so info is untouched). Because sn_search frames are only ever sent to peers recorded as advertising the extension (a per-connection fact set from the extended handshake), and Layer D rides only standard BEP-44/46/51, there is no new reserved bit, DHT verb, or UDP port anywhere in the tree — and the gate fails the build if any codec vector or the vanilla-silence assertion regresses.\n\nInvariant #2 (identity persistence) lives entirely in the identity package: exact-0600 enforcement, seed/pubkey re-derivation on load, hard-fail on mismatch, and auto-create only at the default XDG path (explicit --identity is load-only). Invariant #3 (localhost-only unauth API) is preserved by keeping httpapi's security model as the loopback bind plus the CSRF/DNS-rebind guard, and by giving httpapi no concept of auth tokens or remote sessions — it cannot accidentally become network-trusting because that code does not exist. Invariant #4 (one daemon, three frontends) is enforced by keeping daemon.New the sole constructor with the fixed startup/teardown order, and — critically — by relocating the two places the legacy let frontends diverge (search reconciliation, confirm/flag semantics) into shared owners (searchmux and daemon.Confirm/Flag) so the frontends are pure presentation and CANNOT hold different behavior.

**Key decisions.**

- Extract a `capability` package whose Announced(Sharing,RuntimeFacts) is the ONLY producer of the services mask, consumed by both swarmsearch's peer_announce and httpapi's ServicesReporter — Roots out three §6 defects at once (capability-downgrade-not-on-wire, /aggregate-static-constant, and the drift between them) by construction: there is one function, so wire and readout cannot disagree (§6.1 (capability downgrades never reflected; /aggregate reports 0x2ED not live); §5.1 weird-mask rule; §7-A Q5)
- Split capability into operator-settable Sharing (share_local/file_hits/content_hits) vs daemon-owned RuntimeFacts (Publisher, Reconciliation, Regtest, Companion*); the HTTP/GUI setter mutates only Sharing — Makes the §6 'Save sharing settings clobbers the Publisher bit' defect unrepresentable — Publisher is not in the type the setter can reach, so a partial POST cannot zero it (§6.1 (silent clobber of Publisher bit); §7-I Q54)
- Move three-layer reconciliation into one concurrent `searchmux` shared by daemon-adapter and gui, returning a tuple of the three native response types (no merged type) — Fixes the §6 strictly-sequential /search defect and prevents web/GUI fan-out logic from diverging, while preserving the isolation law that each layer owns its response type reconciled only at the edge (§6.1 (/search sequential); §2.9 layer seam; CLAUDE.md three-search-layers isolation)
- Make Layer-D a swappable RecordBackend seam: legacyKeyword (default, shipping) and aggregatePPMI (off, not load-bearing) — Implements §0's explicit call that legacy BEP-44 is the baseline that must keep working and Aggregate is a cleanly-separated migration target, so §7-C sequencing can be answered without re-architecting (§0 Aggregate endgame; §2.6/§2.7; §7-C Q12-17)
- Replace the bloomPolicy placeholder with a typed `admission` package: named rules that each fail-closed, DefaultPolicy()=deny, permissive policy only test-constructable — Directly inverts the §6 admit-any-unknown defect (0.5 ≥ 0.3 admits every Sybil) into deny-by-default, and makes the endorsement/anchor/crawl signals separately testable (§6.1 (admission gate inverts default-deny); §5.7; §7-B Q8-9)
- Centralize confirm/flag in the daemon (one implementation both httpapi and gui call), and consult trust.IsTrusted before demotion; wire Options.PublisherPubKey — Fixes the §6 cluster of feedback inconsistencies (GUI records attributed sources but HTTP is bloom-only; trusted publishers wrongly demoted; publisher.pubkey never surfaced) by having a single code path (§6.1 (reputation feedback inconsistent; trusted publishers demoted; /status pubkey half-fixed); §7-D Q21-22, §7-I Q53)
- Extract a leaf `record` package owning SignedRecord, SigMessage(), and ElementID() imported by swarmsearch, dhtindex/aggregate, and companion — Eliminates the §5.1/§5.2 latent-bug class of byte-identical derivations that must be manually kept in sync across duplicated definitions, without breaking layer isolation (record is format-neutral, not a cross-layer response type) (§5.1 (record ID duplicated must stay byte-identical); §2.5 sig message; §4.2 non-dependency note)
- Promote the MiniPeer + golden-wire-vector conformance suite into the CI merge gate as `wirecompat`, not testlab-excluded — Turns invariant #1 (mainline wire compat) from a convention into an enforced gate; every codec has frozen byte vectors and a non-advertising peer is asserted to receive zero sn_search frames (§2.11/§2.12 wire-compat matrix; §5.11 (testlab excluded from CI); invariant #1)
- Unify the two regtest env gates into one (SWARTZNET_ALLOW_UNSAFE=1 + testing.Testing()) checked identically at CLI and config layers — Resolves the §6 undocumented dual-gate defect that breaks the project's own testbed; picks the most defensible default (single documented name) per the explicit §7 latitude (§6.1 (two differently-named env gates, none documented); §7-H Q46)

**Self-identified risks.** The RecordBackend seam for Aggregate must be genuinely swappable without leaking PPMI/B-tree assumptions into the legacy path; if the interface is drawn wrong, the §7-C migration re-architects anyway. Mitigation: define the seam against the legacy path first and only add the aggregate impl once legacy passes the full lookup test suite.; Promoting wirecompat/MiniPeer into CI may reintroduce the flakiness that got testlab excluded from -race in the first place (§5.11). Mitigation: keep the multi-client piece-transfer scenarios local-only, but gate on the deterministic golden-vector and single-MiniPeer silence assertions which have no timing dependence.; capability.RuntimeFacts must be updated by the engine at exactly the moments live state changes (start publishing, enter regtest, companion up/down); a missed update silently under/over-advertises. Mitigation: RuntimeFacts is recomputed on every peer_announce from engine getters rather than cached, so it tracks live state by construction.; Centralizing confirm/flag and search in daemon/searchmux risks a fat daemon package. Mitigation: daemon holds only wiring + adapters + the two shared control operations; all logic stays in the leaf packages it delegates to.; The record leaf package couples three layers to one type; a format change now touches swarmsearch, dhtindex, and companion together. Mitigation: golden vectors make an accidental divergence a compile-or-test failure, which is the whole point.; Deny-by-default admission with an empty shipped anchor/seed list (§6.2, §7-B Q8) means cold-start discovery genuinely finds nobody until a trust root ships — the rebuild is correct but inert without operator keys. Mitigation: surface admission counts in /aggregate and log admit-capped/observed so a starved node is distinguishable from a quiet one; treat shipping a curated seeds.json as an explicit release prerequisite, not code.

### SwartzNet Hexagonal Rebuild — "The Wire Lives Only in Adapters"

**Organizing principle.** A pure domain core (torrents, documents, identity, trust, reputation, keyword records) sits at the center and knows nothing about BitTorrent, DHT, Bleve, HTTP, or Fyne — it speaks only value objects and frozen algorithms (tokenizer, chunker, RecordID, reputation/Bloom math, signing payload). Every external system is a replaceable adapter behind a coarse port interface, and the single most important consequence is that *every byte a vanilla peer could observe is emitted by exactly four adapter packages* — making mainline-compat a property of a testable seam rather than a discipline scattered through the code. The application layer orchestrates use cases over driven ports; the three frontends and the daemon are all driving adapters over one assembly, so "one daemon, three frontends" is the composition root by construction and "swap Layer-D legacy↔Aggregate" is a one-line adapter choice.

**Invariant strategy.** The four hard invariants become structural facts, and the mainline-wire invariant in particular becomes testable without a socket. (1) Mainline wire compat: because core and app hold no wire knowledge, every vanilla-observable byte originates in exactly four adapters — swarm-anacrolix (BEP-3/9/10/11 + LTEP handshake), wire-snsearch (sn_search frames), dht-anacrolix + directory-* (BEP-44/46/51 items), and the RecordCodec/signing path (snet.* top-level fields, infohash-preserving). The wire-compat matrix (§2.12 four directions) is written as a test suite against an in-memory VanillaPeer test-double that implements the LtepTransport port and asserts it NEVER receives an sn_search frame, that unknown LTEP keys and future service bits are tolerated, and that a mismatched scope yields reject code 2 — all in-process, no netem. The real anacrolix-vanilla testbed s11 stays as belt-and-suspenders, but the seam is what makes the invariant a compile-and-unit-testable contract, and SendExtension's capability token makes the 'only advertised peers' rule unforgeable. (2) Identity persistence: Identity is a core entity; IdentityVault is a driven port whose Load/Create/Locate result carries an isDefaultPath flag, so 'auto-create only at the XDG default, never regenerate implicitly' is domain policy and the file adapter enforces exact-0600. All publisher-shaped consumers (signing, Layer-D, peer_announce pk) receive the same Identity value — one source, no re-derivation. (3) Localhost-only unauth API: no application port carries any auth concept, so there is no config flag that could open a remote authenticated mode by accident; a future remote surface must be a NEW driving adapter that supplies its own auth, and the existing httpapi adapter's security model is its loopback bind + CSRF middleware, fail-closed. (4) One daemon, three frontends: node.New is the single assembly of driving-port implementations; CLI, web UI, and Fyne depend only on those ports, differing solely in presentation, and all lifecycle order/degraded-start/reverse-shutdown lives in node and nowhere else. The Aggregate migration is clean for the same reason the invariants are: KeywordDirectory is one port with legacy/aggregate/composite implementations, so dual-write, dual-read, and eventual legacy retirement are adapter selections in node.New — the app and domain never learn which Layer-D format is on the wire.

**Key decisions.**

One domain authority makes drift a compile-time impossibility. (§5.1 (RecordID duplicated must stay byte-identical), §5.2 (tokenization contract), §5.5 (2 KiB chunk), §5.6 (Bloom FNV-64a frozen))
- LtepTransport.SendExtension requires a capability-verified peer token minted only from a recorded remote sn_search advertisement; there is no way to send an extension frame to a bare address — Turns the single most load-bearing invariant ('never send sn_search to a non-advertising peer') from a runtime check into a type-level guarantee, and lets the whole wire-compat matrix run against an in-memory VanillaPeer with no sockets. - Announced services bitfield is derived from the live Capabilities value object each handshake, and L1 in-swarm sharing is implemented as a LocalIndex query filtered to core/torrent's active-swarm set — Fixes two verified §6.1 defects at once: capability downgrades never reaching the wire, and L1 sharing nothing. - Queue promotion on completion lives in core/torrent and fires on the FileComplete event independently of the reputation/Bloom adapter — Directly fixes the §6.1 defect where a nil Bloom filter skips promotion and a completed torrent never frees its slot; decoupling is the natural hexagonal outcome since queueing is pure domain and Bloom is a driven port. - Legacy KeywordDirectory is the shipped default (node selects composite for dual-read); Aggregate is a fully-separated adapter, not load-bearing at GA — Matches the provisional vision call to treat legacy as baseline and Aggregate as a clean migration target, and answers §7-C structurally rather than by re-architecting. (§0 ('The distributed-layer endgame'), §7-C Q12-17)

### SwartzNet Rebuild — Vertical Capability Slices

**Organizing principle.** The system is a set of user-observable capability slices (download, search-local, search-swarm, search-dht, authoring/sign, trust/reputation, companion, aggregate) that each own their storage, their wire policy, and their frontend surface end-to-end, sitting on a deliberately thin two-part kernel: a coordination kernel (identity, config, a typed event bus, and a lifecycle composition root) and a policy-free resource substrate (one anacrolix client + DHT server exposed only through narrow typed ports). Slices never import each other; every cross-slice need is a Go interface defined in the CONSUMING slice and satisfied by an adapter wired only at the composition root, while fire-and-forget cross-slice signalling (metadata arrived, file completed, download done) flows through the event bus. The result is that the module map and the build order are the same shape — each slice is a self-contained increment that ships something a user or a peer can immediately observe.

**Invariant strategy.** Mainline wire compatibility (invariant 1) is enforced by capability confinement, then made testable by structural narrowing. Only two slices ever touch the peer wire — slices/download (pure BEP-3/5/9/11/19/27 via anacrolix) and slices/searchswarm (LTEP, confined) — and only slices/searchdht touches the DHT (BEP-44/46/51). No slice can set a reserved bit, open a UDP port, or add a DHT verb because substrate is the sole client owner and its ports expose no such primitive: LtepTransport.Send requires a peer handle that only exists once that peer advertised sn_search in its `m` dict, so 'never send to a non-advertising peer' is a type-level property, not a runtime check. Because the entire non-standard surface lives in the frozen contracts/* leaves plus swarm's state machine, wire-compat testing decomposes into three cheap, independent tiers: (a) golden byte-vector tests attached to each contracts leaf (tokenize, RecordID, signing payload, KeywordValue, PPMIValue, SNAGG page/trailer, RIBLT symbol) so any byte drift fails a unit test; (b) a vanilla-MiniPeer observer that asserts a stock BEP-10 handshake with an empty `m` dict never receives an sn_search ext-id and that reserved bits are unchanged; (c) a four-direction wirematrix test against the pinned anacrolix v1.61.0 client (download-from-us / download-from-vanilla / DHT-health / two-node negotiation with reject-code-2 on scope mismatch). The matrix is small precisely because the novel surface is confined.

Identity persistence (invariant 2) has exactly one implementation, kernel/identity, with 0600-exact enforcement, seed-derived pubkey verification, and auto-create only at the default XDG path; every publisher-shaped slice (searchdht, authoring, companion, aggregate, trust) consumes the same Identity port, so no slice can regenerate or shadow it. Localhost-only unauth API (invariant 3) is owned solely by frontend/httpapi: the bind address, CSRF/DNS-rebind guard, and 1MiB body cap live there and nowhere else; slices contribute route-groups but cannot change the bind, and a non-loopback bind emits the loud one-time warning. One-daemon-three-frontends (invariant 4) is guaranteed because kernel/lifecycle is the only composition root — it constructs the kernel, instantiates every slice Service, wires all consumer→provider adapters and event subscriptions, and centralizes the degraded-start and reverse-teardown policy; the three hosts (httpapi, cli, gui) are pure presenters over slice Service ports and share that one Daemon, so subsystem lifecycle exists in exactly one place.

### Invariant risks

- The transport-token graft (invariant #1's strongest structural guard) risks an engine↔swarmsearch import cycle as described. The doc lists `LtepTransport.SendExtension(peer PeerToken, frame []byte)` and `PeerToken` under ENGINE's Key types, while requiring swarmsearch to send every frame through it. But swarmsearch is the CALLER of SendExtension, so if PeerToken/Transport are engine types, swarmsearch must import engine — and engine already imports swarmsearch (inbound-frame dispatch to Handler, handler wiring, LocalSearcher adapter). That is a compile cycle. The legacy avoids it precisely by defining the `Sender`/`LtepAdvertiser` seam IN swarmsearch and sending by a plain address string; the graft's whole value (a bare address is unsendable — you need a token minted from a recorded advertisement) forces the token type to be visible to swarmsearch's call site. If the team 'resolves' this by keeping the token in engine and NOT threading it through swarmsearch, the type-level guarantee silently degrades to convention (the architecture's own Open Risk #4).  
  **Fix:** Define the opaque `PeerToken` type and the `Transport`/`SendExtension` interface IN swarmsearch (or a tiny shared contracts leaf), mirroring the legacy Sender seam. Engine mints tokens in its PeerConnAdded/extended-handshake path (only when the remote advertised sn_search in its m-dict — NOT gated on peer_announce, so a token-holding peer that never announced is still answered per §5.1) and injects an implementation of swarmsearch's Transport. State this ownership explicitly in ARCHITECTURE so the DAG claim is provable and engine→swarmsearch stays one-directional.
- Slice 0 DoD 'binding to a non-loopback address is refused' tightens invariant #3 beyond what the spec documents. SPEC §2.9 and §5.9 (line 899) state the server DOES bind non-loopback addresses if asked ('operators may front their own auth') and emits a loud one-time UNAUTHENTICATED warning; the security model is loopback-bind + CSRF, not a hard refusal. Refusing removes the documented ListenHost / `--api-addr 0.0.0.0` capability. This is a defensible invariant-hardening but it is an unrecorded behavior change (no assumption logged for it).  
  **Fix:** Either keep the warn-and-bind behavior (loopback default, non-loopback allowed with a loud warning) to match §2.9/§5.9, or record the refusal explicitly as a deliberate tightening of invariant #3 in the Assumptions section so it isn't a silent divergence.

### §5 rules at risk of being lost

- §5.5 MIME resolution consults SwartzNet's extTypes override map BEFORE stdlib mime.TypeByExtension. This is load-bearing, not cosmetic: Go's builtin table lacks .txt, so on Alpine/scratch deployments plaintext extraction silently skips EVERYTHING without the override, and .ts must resolve to TypeScript not MPEG-TS; stdlib results also need any ';charset=' suffix stripped. Not surfaced in the indexer/extractors design — a golden/table test candidate.
- §5.6 signature-verification taxonomy is three-way, not two: missing snet fields → ErrNotSigned (benign); crypto failure → ErrBadSignature (firm tamper, struct still populated); but wrong pubkey/sig LENGTHS → a plain error that is NEITHER sentinel. The architecture (contracts/sign, signing) names only ErrNotSigned/ErrBadSignature; UIs distinguish benign-vs-tamper on this taxonomy, so the third case must be preserved.
- §5.5 raw .html/.htm files are indexed by the PLAINTEXT extractor with tags left in (text/html is in plaintext's accept list); the tag-stripping HTML walker is used ONLY for XHTML inside EPUB/ZIM. There is deliberately no standalone HTML extractor. A rebuild that 'improves' this by adding a proper HTML extractor silently changes indexed content for every .html file (§7-Q40).
- §5.2 keywords whose UTF-8 salt exceeds 64 bytes are DROPPED, never truncated (truncation would alias distinct keywords onto one DHT target). Not called out in contracts/dhtschema or contracts/token; must be preserved as a hard drop.
- §5.9 the web UI injects Bleve highlighter fragments and highlighted names via innerHTML on the explicit assumption that Bleve pre-escapes text and only adds <mark> tags. A rebuild of either the highlighter or the web UI that drops that escaping guarantee becomes a stored/reflected XSS. Not mentioned in the httpapi/web design.

### §6 defect watch-items

- No §6.1 verified defect is re-encoded — the architecture's defect-class table is thorough and each fix is structural.
